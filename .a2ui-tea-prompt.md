# a2ui-tea: Bubble Tea TUIs configured on the fly by A2UI messages

## Goal, in George's words

> I want to combine bubble tea, with the ability to configure it on the fly with the a2ui pattern.
> Create a repo under my name for that.

The repo exists and is empty: https://github.com/GeorgePearse/a2ui-tea (public, this clone, remote `origin`
over SSH). Build it here, commit to `main` directly (personal repo, no PR needed), push.

## What it is

A Go library + CLI. An agent (or anything) streams **A2UI** messages (Google's declarative JSON protocol for
agent-driven UIs: `createSurface`, `updateComponents`, `updateDataModel`, `deleteSurface`, plus user actions
flowing back) and the terminal renders them as a **Bubble Tea** program whose component tree, layout and data are
defined at runtime, so the UI changes while it runs with no recompile and no restart. Humans interact
(focus, type, press buttons, pick choices) and those interactions go back out as A2UI user-action messages.

Spec and reference material (read these first, implement the current spec, not what you remember):
- https://github.com/a2ui-project/a2ui — `docs/public/reference/messages.md`, `reference/components.md`,
  `concepts/data-binding.md` (JSON-pointer paths into the surface's data model, templated `ChildList`),
  `concepts/actions.md`, `concepts/catalogs.md`, `guides/renderer-development.md`,
  `guides/defining-your-own-catalog.md`.
- The standard catalog: `catalogs/basic/v1/catalog.json` (the 16 BasicCatalog components: Text, Icon, Image,
  Video, AudioPlayer, Divider, Button, TextField, CheckBox, ChoicePicker, Slider, DateTimeInput, Card, List,
  Tabs, Modal, plus Row/Column containers) and its examples `catalogs/basic/v1/examples/*.json` (30+ sample
  surfaces: login form, flight status, product card, music player, incremental update, complex layout...).
  Fetch them with `gh api repos/a2ui-project/a2ui/contents/<path> -H 'Accept: application/vnd.github.raw'`
  and vendor the examples under `testdata/` with their licence notice (A2UI is Apache-2.0).
- Prior art to look at, not copy: `a2ui-tui` in https://github.com/liangdi/a2ui (ratatui, Rust, 18 components,
  MIT) and `examples/genui_tui_agent` in https://github.com/RandalSchwartz/BlocSignal (Dart; its ASCII
  conventions `[x]`/`( o)`/`[====----]` are good).

## Design decisions

1. **Layout: Go module `github.com/GeorgePearse/a2ui-tea`.** Packages, keep them few:
   - `a2ui`: protocol types, message parsing (all versions in the current spec; also accept `version: "v0.9.1"`
     messages of the same shape, that is what one real producer emits), the surface store (components by id,
     data model with JSON-pointer get/set, `ChildList` template expansion, `checks`/CheckRule evaluation), and
     the outbound user-action message type. No terminal code in here.
   - `tea` (or `render`): the Bubble Tea `Model`. Its `View()` walks the surface tree at render time and
     composes it with Lip Gloss; a layout pass gives Row children widths by weight / intrinsic width and
     Column children their heights, so a layout the agent invents at runtime renders without any Go changes.
     Focus ring across interactive components (Tab / Shift-Tab), Enter on Button, text input via the
     `bubbles/textinput`, CheckBox toggles, ChoicePicker single/multi, Slider with arrows, Tabs with arrows,
     Modal overlays the surface, List renders template children. Image/Video/AudioPlayer render a labelled
     placeholder box (alt text + URL), with Kitty/Sixel inline images as a later issue, not now.
   - `catalog`: the component registry. BasicCatalog registered by default; a caller registers extra components
     (name → Go renderer) so a custom catalog id works without forking. This is the extension point.
   - `cmd/a2ui-tea`: the CLI. Inputs: `--stdin` (one JSON message or array per line), `--file <path>` with
     watch (re-render on change), `--url <http(s)>` for SSE or newline-delimited streaming, and `demo`.
     Output: user actions as JSON lines on stdout (stdin/file modes) or POSTed back (url mode); `--log` for a
     debug trace on stderr. Exit cleanly on `deleteSurface` of the last surface or `q`/Ctrl-C.
2. **"On the fly" is the point.** `demo` runs a scripted sequence that creates a surface, then every ~800 ms
   sends `updateComponents` / `updateDataModel` messages that restructure it (add a row, swap a card for a tab
   set, open a modal, change a list's data) while the user can keep tabbing through it. Record this with
   `vhs` (charmbracelet/vhs; install it if missing, it needs ttyd + ffmpeg, `go install
   github.com/charmbracelet/vhs@latest`) as `docs/demo.gif` and put it at the top of the README. If vhs cannot
   be installed on this box, use `asciinema` + `agg`, and say which in the commit.
3. **Golden tests.** For every vendored spec example, a test renders the surface to a string at widths 60, 80
   and 120 and compares with `testdata/golden/<name>_<width>.txt` (regenerate with `-update`). Unit tests for
   the data model (pointer get/set, template expansion, CheckRule), message parsing (every message type, bad
   input), and interaction (a Button press yields the right user-action message; typing into a TextField
   updates the bound data-model path). `go test ./...` and `go vet ./...` clean; add `golangci-lint` config
   only if it is already installed.
4. **Dependencies**: `charmbracelet/bubbletea`, `bubbles`, `lipgloss` at their current stable majors (check
   `go list -m -versions`; Bubble Tea v2 may be current, use whichever is the documented stable, and say which
   in the README). Nothing else beyond the standard library unless there is a strong reason.
5. **README**: the gif, a 10-line "what it does", install (`go install github.com/GeorgePearse/a2ui-tea/cmd/a2ui-tea@latest`),
   the three input modes with a copy-paste example (`echo '<message>' | a2ui-tea --stdin`), the library API
   (register a custom component in ~15 lines), what is and is not implemented from the spec (a table), and
   licence. MIT `LICENSE` with George Pearse as the holder, year 2026.
6. Idiomatic Go, small files, no narrative comments; doc comments on exported identifiers only.
